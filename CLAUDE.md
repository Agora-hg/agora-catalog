# Агора Каталог V0 — правила репозитория

SEO-каталог поставщиков упаковки по Москве. Отдельный продукт, отдельный репозиторий.
**Не путать с четырьмя репо основной Агоры** (`D:\rauanprojects\agora\{backend,admin,lead-enricher,tgbot}`) —
туда не лезть вообще, там работают другие люди.

## Что это и зачем

Человек ищет в Яндексе «гофрокороба Москва» → попадает к нам → видит проверенные
карточки поставщиков → оставляет заявку → её руками разбирает оператор.
Проверка гипотезы перед большой Агорой. SEO — не приятный бонус, а весь смысл.

## Стек и почему

TypeScript везде. **PHP на машине владельца нет**, Node 22 есть — на Laravel каждый
воркер сначала полдня ставил бы PHP и не мог прогнать тесты локально.

- `packages/db` — Drizzle + PostgreSQL. Схема здесь единственный источник истины.
- `apps/api` — Node, публичный API + операторская панель. **Только московский VPS.**
- `apps/web` — Next.js, публичный каталог. Хостинг — вопрос DNS, см. ниже.

## Целевая версия Postgres — 14

На проде (общий сервер `178.88.115.213`) стоит **PostgreSQL 14.24**. Апгрейдить нельзя:
на этом же экземпляре живут чужие проекты. Dev на PGlite — это PG17, то есть
**dev новее прода**, и что-то может работать локально и упасть на сервере.

Практически: **никакого синтаксиса PG15+**. Уже наступили один раз —
`NULLS NOT DISTINCT` в уникальном индексе пришлось переписывать на `COALESCE`.
Сомневаешься в фиче — проверь на сервере, база `agora_catalog` уже создана.

## Границы, которые нельзя переступать

1. **Персональные данные не покидают РФ.** Заявки, отклики, claims, панель — только
   `apps/api` на московском VPS. Форма на фронте постится напрямую в `api.<домен>.ru`.
2. **Никаких Vercel-only возможностей** в `apps/web`: ни Edge Middleware, ни Vercel KV/Blob,
   ни Vercel Image Optimization. Причина: Vercel в 2026 частично фильтруется из РФ,
   а YandexBot краулит из российских сетей (AS13238). Если обход просядет, переезд
   на московский VPS должен быть сменой DNS за час, а не переписыванием приложения.
3. **Схему БД меняет только тимлид.** Нужна колонка — пиши в карточку задачи, не в миграцию.
   Семь воркеров, правящих одну схему параллельно, — это гарантированный конфликт миграций.
4. **`description_raw` наружу не отдаётся никогда.** Это чужой текст с Я.Карт.
   На сайт идёт `description` — наш.
5. **Физического DELETE компаний не бывает.** Только `is_deleted` + причина.
6. **checko.ru и любые сервисы пробива не парсим.** Когда обогащение ЕГРЮЛ вернётся —
   только через DaData. В V0 его нет вообще: `inn`, `ogrn`, `okved`, `egrul_status`
   пустые, блок реквизитов на карточке не показывается.
7. **Пока сайт стоит не на своём домене — он закрыт от индексации.** `robots.txt`
   с `Disallow: /` и `X-Robots-Tag: noindex` на временном хосте, снимается одним
   переключателем в env при выдаче домена. Причина: если Яндекс проиндексирует
   временный адрес, после переезда получим дубли, склейку и потерянные недели —
   а SEO здесь единственный смысл продукта.

## Чего в V0 нет — не добавлять по своей инициативе

MOQ, сроки, доставка, брендирование в карточках компании (это свойства оффера, а не фирмы).
226 категорийных тех-полей и EAV из xlsx. Регистрация покупателей и поставщиков,
личные кабинеты, оплата, сделки, SKU, цены, остатки, чат, AI-матчинг, CRM.
Города кроме Москвы — схема готова, данных не будет.

Правило от Стаса: **чего нет в описании задачи — того нет.** Придумал полезное —
сначала в карточку, потом в код.

## Работа

Один воркер — одна карточка — один git worktree. Ветка `task/<id>-<слаг>`.
Карточки: `D:\rauanprojects\orhecstrator\tasks\agora\`.
Перед PR: `npx tsc --noEmit` чисто и тесты на фикстурах зелёные.
Сдача — не «готово», а вывод команд и цифры.
