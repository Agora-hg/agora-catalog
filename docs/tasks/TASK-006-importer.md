## Зависит от
Схема `packages/db/src/schema.ts` — готова, менять нельзя. JSONL от парсера (TASK-005) —
можно начинать на фикстурах, не дожидаясь реального прогона.

## Goal
Поток из пункта 3 спеки: парсер → сырьё → нормализация → поиск дублей → Company.
Парсер НЕ пишет в companies напрямую. Сначала всё падает в `raw_yandex_orgs` как есть.

## Что сделать
`apps/api/src/import/` + CLI `npm run import -- --file <jsonl> --batch <имя>`:

1. Заливка JSONL в `raw_yandex_orgs`, идемпотентно по паре `oid` + `batch`.
2. Нормализация: телефоны в E.164, сайт без utm и без редиректа Яндекса, адрес
   чистится от ведущего «Москва, », город и регион выделяются в свои поля.
3. Дедуп строго в этом порядке (пункт 3 спеки):
   ИНН → если нет, домен сайта → если нет, name + phone.
   Совпало — UPDATE существующей записи, не INSERT. Не совпало — новая.
4. `company_sources`: строка на каждый импорт, `source_type = 'yandex_maps'`,
   в `payload` — сырьё. Это чтобы перепрогнать нормализацию, не парся Яндекс заново.
5. Автомэппинг категорий по `CATEGORY_SEED[].match` из `packages/db/src/seed-categories.ts`
   (рубрики с карт + название + описание) → `company_categories` с `is_auto = true`.
6. `description_raw` = описание с карт. `description` НЕ заполнять, это задача тимлида.
7. Статусы (пункт 4 спеки): нашли в этом прогоне → `active`. Компания была в базе,
   в новом прогоне её нет → `unknown`. **`inactive` импортёр не ставит никогда** —
   это делает только оператор после проверки.

## Приёмка
- Тесты на фикстурах: 20 записей, среди них 3 дубля по ИНН, 2 по домену,
  2 по name+phone, 1 вообще без контактов. Все случаи разведены правильно.

  сколько обновлено, сколько осталось без категории.
- `npx tsc --noEmit` чисто.
