# Как здесь работать — для воркеров

Читать целиком до первой строки кода. Всё, что тут написано, проверено на этой машине,
это не общие рекомендации.

## 0. Что на машине есть и чего нет

Есть: Node 22, npm 10, git, scoop, winget.
**Нет: PHP, Docker, Podman, WSL.** Не пытайся поднять базу в контейнере — ставить нечего.

**Нативный Postgres на этой машине не ставится.** `scoop install postgresql` проходит,
но `initdb` падает:

```
FATAL: invalid byte sequence for encoding "UTF8": 0xd0 0xe0
```

`0xd0 0xe0` — байты «Ра» в cp1251, то есть кириллица в имени пользователя Windows
(профиль `C:\Users\<кириллица>`). Не лечится ни ASCII-путём для данных, ни подменой
USERNAME / TMP / LANG, ни `--locale=C` — проверено трижды. Не трать на это время.

Поэтому в dev база — **PGlite**: настоящий Postgres, собранный в WASM, приезжает
npm-пакетом. Ставить нечего, сервиса нет, работает на любом пути.

## 1. Поднять окружение (одна команда)

```bash
npm install                      # из корня репозитория, workspaces
npm run -w @agora/db setup       # миграции + категории
```

Всё. База в `packages/db/.pgdata/`, она в `.gitignore`. Гонять `setup` можно сколько
угодно: миграции ведёт штатный мигратор drizzle (таблица `__drizzle_migrations`),
категории — upsert по slug. Проверено: первый прогон создаёт 72 категории, второй — ноль.

Подключение **только** через `getDb()` из `@agora/db`. Своих пулов и своих клиентов
PGlite не создавай: там же подключается расширение `pg_trgm`, без которого развалится
поиск.

```ts
import { getDb, closeDb, companies } from '@agora/db'
const db = await getDb()
```

**В любом CLI-скрипте обязателен `await closeDb()` в конце.** Проверено на живом
движке: если процесс на PGlite завершится без `close()`, папка `.pgdata` остаётся
в грязном состоянии, и следующий запуск подвешивается внутри `PGlite.create()`
наглухо — без ошибки и без таймаута, просто висит. Со стороны это неотлаживаемо,
поэтому правило жёсткое.

Залипло — `rm -rf packages/db/.pgdata && npm run -w @agora/db setup`.

Когда появится реальный Postgres на сервере, тот же код пойдёт в него: достаточно
задать `DATABASE_URL=postgres://...`. Ветку выбора движка в `packages/db/src/index.ts`
не трогай.

## 2. Своя ветка и свой worktree

Семь воркеров в одной рабочей копии затопчут друг друга. Каждому — отдельный worktree:

```bash
git worktree add ../agora-catalog-<id> -b task/<id>-<слаг>
```

Ветка ровно та, что указана в карточке (`branch:` во фронтматтере).
**В `main` не коммитить никогда.**

## 3. Границы, которые нельзя переступать

Полный список в `CLAUDE.md`, здесь самое частое:

1. **Схему БД (`packages/db/src/schema.ts`) не менять.** Нужна колонка или индекс —
   пиши в конец своей карточки блоком `## Нужно от тимлида` и продолжай остальное.
   Семь воркеров, параллельно правящих схему, — это гарантированный конфликт миграций,
   разгребать его дороже, чем подождать.
2. **Формы ответов API из `docs/API.md` не менять.** На них параллельно пишется фронт.
   Поля не переименовывать, не добавлять, не убирать.
3. **Персональные данные не покидают РФ.** Заявки, отклики, обращения, панель —
   только `apps/api`. На фронте формы постятся напрямую в `api.<домен>.ru`.
4. **`description_raw` наружу не отдаётся никогда.** Это чужой текст с Яндекс.Карт.
   На сайт идёт `description` — наш.
5. **Физического DELETE компаний не бывает.** Только `is_deleted` + причина.
6. **checko.ru и прочие сервисы пробива не парсить.** Обогащение ЕГРЮЛ в V0 снято
   решением владельца: `inn`, `ogrn`, `okved`, `egrul_status` приходят `null`,
   блок реквизитов на карточке не рисуется. Вернётся — только через DaData.
7. **Никаких Vercel-only возможностей** в `apps/web`.
8. Не заходить в чужую карточку. Увидел баг в соседней области — напиши о нём
   в отчёте, не лезь исправлять.

## 4. Чего в V0 нет

MOQ, сроки, доставка, брендирование в карточках компании. 226 категорийных тех-полей
и EAV из xlsx. Регистрация покупателей и поставщиков, кабинеты, оплата, сделки,
SKU, цены, остатки, чат, AI-матчинг, CRM. Города кроме Москвы.

Правило владельца продукта: **чего нет в описании задачи — того нет.**
Придумал полезное — сначала строкой в карточку, потом в код.

## 5. Definition of done

Задача сдана, когда выполнено ВСЁ:

- пункты раздела «Приёмка» из карточки выполнены, каждый подтверждён выводом команды;
- `npx tsc --noEmit` — чисто;
- тесты на фикстурах зелёные, и они проверяют поведение, а не то, что код запускается;
- нет закомментированного кода, нет `console.log` отладки, нет `any` без причины;
- работает на пустой базе с нуля: `rm -rf packages/db/.pgdata` → `setup` → твой код.

## 6. Как сдавать

Отчёт последним сообщением, по этой форме:

```
## Что сделал
3-5 строк, без пересказа карточки.

## Проверено фактом
Команда → её реальный вывод. Не «тесты проходят», а вывод раннера.
Не «работает», а curl с телом ответа.

## Что не сделал и почему
Честно, одной строкой на пункт. Пусто — так и напиши.

## Нужно от тимлида
Колонки в схеме, поля в API, доступы. Пусто — так и напиши.
```

**Не писать «готово», если не прогонял.** Врать про статус — единственное,
за что работа не принимается целиком и переделывается с нуля.
Ошибся — одна строка и дальше, без самобичевания.

## 7. Если застрял

- Схема мешает → блок «Нужно от тимлида», делай остальное.
- Нет доступа (SMTP, домен) → замокай на интерфейсе, тесты на фикстурах,
  в отчёт строкой «ждёт доступ». Не выдумывай ключи и не подставляй чужие.
- Карточка противоречит `CLAUDE.md` → прав `CLAUDE.md`, пиши о противоречии в отчёт.
- Не понял предметную область → в `docs/API.md` и `packages/db/src/schema.ts`
  комментарии объясняют почему, а не только что. Читай их, там ответы на большинство
  вопросов «а почему так».
