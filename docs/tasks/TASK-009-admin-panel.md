## Goal
Операторская панель Агоры, а не кабинет поставщика (пункт 11 спеки). Единственный
пользователь — оператор. Задача Рауана про обзвон живёт здесь.

## Что сделать
`apps/api` + серверные страницы под `/admin` (SSR, без отдельного SPA):

1. Авторизация email + пароль (`admin_users`), сессия в httpOnly cookie.
2. **Список компаний для обзвона — главный экран.** Фильтры: не обзвонены;
   ликвидированные по `egrul_status` отдельно; без телефона отдельно.
   Видно телефон, сайт, адрес и описание с карт — чтобы было о чём спрашивать.
3. По компании: редактировать поля, `is_verified`, категории, `called_at` + заметка.
4. **Удаление мягкое.** Кнопка «Не существует» → модалка с обязательной причиной →
   `is_deleted = 1`, `deleted_reason`, `deleted_at`, `deleted_by`. Физического DELETE
   в панели нет вообще. Удалённые видны в отдельной вкладке вместе с причинами —
   из этого потом собирается статистика.
5. `status` (active/unknown/inactive) в панели **не редактируется**, показывать
   read-only. Им управляет парсер, иначе следующий прогон перезатрёт работу оператора.
6. Обращения `company_claims`: список, разбор, применить или отклонить.
7. Ручная очередь несматченных DaData из TASK-007: показать кандидатов, принять один.
8. Категории: создать, переименовать, включить-выключить, менять порядок.
   Стас отдельно просил добавлять их сам.

## Приёмка
- Удалил компанию с причиной → она исчезла из публичного API, но лежит в базе
  с причиной и датой. Проверить оба факта, не один.
- Причину нельзя не указать: пустая форма не проходит.
- Прогон вслепую: человек, не читавший эту карточку, находит экран обзвона и удаляет
  компанию без подсказок. Не нашёл — переделать навигацию.

## Границы
Схему не трогать. Красоту не наводить: внутренний инструмент, важна скорость работы
оператора, а не дизайн.
