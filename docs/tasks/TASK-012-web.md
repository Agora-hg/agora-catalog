## Goal
`apps/web` — Next.js 15, App Router. Основная и единственная страница по спеке:
«Каталог поставщиков упаковки». Плюс посадочные по категориям — там весь SEO-объём.

## Что сделать
1. Шапка: логотип, Каталог, Заявки, поиск по компаниям и упаковке. Без лишнего.
   **«Заявки» — заглушка** с текстом строго по спеке Стаса: заявок пока нет,
   хотите разместить — отправьте описание запроса на почту. Клик по заглушке
   считать событием: смысл заглушки в том, чтобы понять, сколько людей туда пойдёт.
2. Слева фильтры: категория упаковки, тип продукции (второй уровень дерева), город.
   **MOQ, сроков, доставки и брендирования НЕТ.** Этих данных не существует,
   Стас их вычеркнул. На скриншоте они есть — скриншот здесь не источник истины.
3. Центр — карточки: название, адрес, описание (наше, не с карт), основные категории,
   «Информация проверена <дата>», кнопки «Подробнее» и «Сайт».
4. «Подробнее» — мини-карточка: телефон, адрес, часы работы, все категории, ссылка на сайт.
   **Блока реквизитов (ИНН, ОГРН, ОКВЭД) в V0 нет** — обогащение ЕГРЮЛ отложено
   решением владельца, поля приходят `null`. Карточка обязана выглядеть законченной
   без них, а не показывать «ИНН: —». Появятся данные — добавим блок отдельной задачей.
5. Справа блок «Нужна упаковка?» → форма заявки.
   **Форма постится напрямую в `api.<домен>.ru`, минуя хостинг фронта** — 152-ФЗ,
   персональные данные не идут через зарубежные серверы.
   Почту открытым текстом на странице не печатать: соберёт спам за недели. Только форма.
6. Внизу карточки обязательно: «Вы представитель этой компании?
   Сообщить об ошибке / обновить информацию».
7. **SEO-обвязка. Без неё задача не сдана — в ней весь смысл проекта:**
   - SSR или ISR с ревалидацией 15 минут. Список компаний не рендерить на клиенте.
   - посадочные `/category/<slug>` и `/category/<slug>/moskva`: «гофрокороба в Москве»
     и есть тот запрос, по которому идёт трафик, а не главная страница;
   - `sitemap.xml` (все категории и все компании) и `robots.txt`;
   - микроразметка Schema.org: `Organization` / `LocalBusiness` на карточке компании,
     `BreadcrumbList` на страницах;
   - канонические URL, `<title>` и `<meta description>` из полей категории;
   - страницы компаний по `slug`, внутренние ID в URL не светить.
8. **Пока домена нет — сайт закрыт от индексации.** `robots.txt` с `Disallow: /`
   и заголовок `X-Robots-Tag: noindex` на временном хосте, снятие — одним флагом
   в env (`PUBLIC_INDEXABLE=true`). Причина: если Яндекс проиндексирует временный
   адрес, после переезда на домен получим дубли, склейку и потерянные недели.
   Всю SEO-обвязку при этом делать сразу и полностью — она проверяется в сыром HTML,
   а не индексом.
9. **Никаких Vercel-only возможностей**: ни Edge Middleware, ни Vercel KV/Blob,
   ни Vercel Image Optimization. Причина в `CLAUDE.md`: приложение должно переезжать
   на московский VPS сменой DNS за час, потому что Vercel в 2026 частично фильтруется
   из РФ, а YandexBot краулит из российских сетей.

## Приёмка
- `curl` по странице каталога и по странице компании: в СЫРОМ HTML видны названия
  компаний, описания и разметка Schema.org. Если контент появляется только после JS —
  задача не сдана. Это ровно тот случай, ради которого выбирался серверный рендеринг.
- Страница открывается и читается при полностью выключенном JS.
- `sitemap.xml` отдаёт все категории и все не удалённые компании, ссылки живые.
- Валидатор микроразметки Яндекса не ругается.
- Lighthouse по мобильной версии: цифры производительности и SEO в отчёте.
